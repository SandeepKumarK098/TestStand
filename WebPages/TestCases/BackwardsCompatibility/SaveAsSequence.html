Test Case Scenario
National Instruments Confidential

Save sequence files as previous versions

Backwards Compatibility



Test Description

 

Verify a new sequence file format can be saved and loaded in previous TestStand versions, including maintenance releases that do not bump file versions.

Test Procedure

 

  • For a maintenance release, try opening files from the maintenance release in the previous release, and vice versa. Ensure that files are not marked for save. Ensure that type conflicts do not occur and that the type palette files do not need to be saved.
  • Try saving various sequence files in previous formats by selecting "Save As" and changing the "Save As Type" to "TestStand x.x.x Sequence File."
  • Try to create sequences containing step types and adapters that were inserted in the most recent versions of TestStand and save the sequence as a previous version. For example (for TestStand 3.1) create a sequence containing new flow control and LVRT steps and save it as a previous version.
  • TS 2022 and later: Create a step type that has a LV pre-step, post-step and a LV default module specified. They can be configured to point to any LV VIs. Drop an instance of this step type in the sequence file. Save the file for previous to TS 2017. Verify there are no errors. Close the current file. Verify the saved file opens correctly in the current version.
  • For TestStand 3.1 if there were some steps that are not backward compatible 100% with previous versions of TestStand a warning message will be displaying indicating that there were some problems and that a log file was created containing the details. Try to view the log file and make sure the file contents make sense.
  • Try to save as in all the available previous formats.
  • Delete the compatibility type palette files and make sure TestStand errors – try all versions.
  • Make sure the “Links” property is removed from all files saved with a version less than 3.5.
    • Open a sequence and add a message pop up step to it.
    • Save the sequence as TS 3.5 and TS 3.0 sequence.
    • Check that the link property exist  under requirement for TS 3.5 sequence and  not present in TS 3.0 sequence using the method shown below
    • Use notepad to open the two sequence files ( or a diff tool) to check for the missing links property
    • The link property is shown below :
      •  [DEF, SF.Seq[0].Requirements]
        Links = Strs
  • Make sure that flow control types are converted to label steps for TestStand versions less than 3.1.
