Test Case Scenario
National Instruments Confidential

LabVIEW RT

LabVIEW Build Validation


Test Description

Validate that TestStand - LabVIEW Integration for using Real-Time is working as it should.

Test Procedure

 

  • Install latest LV Build
  • Install the latest Driver CD select the following items:
    • NI-DAQmx (8.0 or later)
    • Traditional NI-DAQ (7.4 or later)
    • NI-488 (2.2.4 or later)
    • NI-VISA (3.4 or later)
    • IVI Compliance Package (2.3 or later)
  • Install the latest version of TestStand.
  • To run a VI on a remote system, open the advance settings on a LV step and select "Run VI on a Remote Computer"
  • Specify the remote host by expression and by its name.
  • While the VI is running on the RT system, turn it off and see what happens. Make sure the VIs take a while to finish so you can have time to shutdown the RT system or disconnected from the network.

 

  • Download the following on RT Box:
    • A VI that is part of a LLB.
    • A VI that uses a subVI that is part of a project library.
    • A VI that is part of a project library.
    • A VI that uses a global DAQmx Task.
    • A VI that uses an XNode.
    • A VI that uses an XControl.
    • A VI that uses a typedef.
    • A VI that uses GPIB.
    • A polymorphic VI.
    • A VI that uses Network Variables.
    • An Express VI.
    • A VI from the LabVIEW analysis library

 

 

  • Ensure that when TestStand is configured to use the Batch or Parallel model, steps configured to execute VIs on different Remote Targets, using expressions for Target IP Address, are ALWAYS executed on the specified target only. Read CAR 3HUARRRR as a reference.

 

  • Checking load and unload
    • Create a VI that returns all the VIs in memory
    • Specify several LV steps and change the loading and unloading options to "Load dynamically" and "Unload after step executes" of some of the steps
    • Sprinkle the call to the VI that returns all VIs in memory and verify that all VIs that have their unload option to "Unload after step executes" are not in memory
    • All the LV calls above should be to the same remote machine
  • Try changing the TCP/IP port to something other than 3363.  Verify that a connection is made.  Make sure you call "Unload All Modules" first before attempting to run the VIs with the new TCP/IP port.
  • Close TestStand. Now, open the cfg/TestExec.ini file and remove the line beginning with "_FlexGAdp_RTSPath" in the [Config._AdapterCfg] section.  In TestStand 2010, the property was renamed to _FlexGAdp_RTSVersion. This will tell TestStand that no Run-Time Engine has never been selected. Now, try running the sequence with the remote calls. They should still work without any problems.
  • Some use cases to try out.
    • Try calling 2 VIs of the same name but from different locations on LabVIEW Real-time and it should error out.
    • You can fix the above problem by putting the duplicate VIs under a project library
