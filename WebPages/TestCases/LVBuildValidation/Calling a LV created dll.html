Test Case Scenario
National Instruments Confidential

Calling a LabVIEW Created DLL

LabVIEW Build Validation

Test Description

Making sure that calling an LV created DLL works as expected.

Test Procedure

NOTE: This test has already been automated & the files can be found under //TestStand/Tests/TS Automated Tests/4.5/LV Built DLLs/.  The manual test plan is to test the latest LV versions and to add test files to the automated test. Add files for the current LV version to Perforce ONLY if it the LabVIEW is a released version (do not add files that were created in a pre-release build since the DLL created will not run with later builds of the same version.)

  1. Install the latest build of LabVIEW on a clean machine.
  2. Install the latest version of TestStand.
  3. Sync the files under //TestStand/Tests/TS Automated Tests/4.5/LV Built DLLs/ & check that a folder coressponding to the latest LV version that you are testing exists. (Ex: If you are testing LabVIEW 2010, ensure there is a folder called "10.0" under  ../4.5/LV Built DLLs/.
    • If it does and you are testing a released version of LabVIEW skip to step 8.
  4. Make a  copy of the previous LabVIEW version's folder & rename it to the current LabVIEW version (LabVIEW 2011 should be 11.0). Make this folder writeable, & mass compile it with the latest LabVIEW.
  5. Currently the test calls LV DLLs that pass simple numbers, strings & arrays. If you require another data type to be tested, create a VI that takes this type as input/output. Add this VI to the project & also to the Build Spec for the DLL. Also add a step that calls this new function to ../4.5/LV Built DLLs/<LV Version>/CallLVBuiltDll.seq with an appropriate validation check. Ensure that you retain the sequence files in TS 4.5 when saving.
  6. Open the project called  "CreateLVDll.lvproj" & build the Build Spec for the DLL. Correct the destination path of the build to the folder where the project is present & build it. (For LabVIEW 13.0 and greater, be sure to update both the 32-Bit and 64-Bit projects accordingly.)
  7. Check in these files to perforce under //TestStand/Tests/TS Automated Tests/4.5/LV Built DLLs/. (Do this only if you are testing with a released LV version).
  8. Run //TestStand/Tests/TS Automated Tests/4.5/LV Built DLLs/CallDllSequences.seq and validate that it passes.
