Test Case Scenario
National Instruments Confidential

Operator Interfaces, Process Models and LabVIEW Environments

LabVIEW Build Validation



Test Description

Make sure that the ActiveX and Runtime LabVIEW environments work as expected under the Sequential, Parallel and Batch models using the Sequence Editor and provided Operator Interfaces. This test is mostly automated. Just follow the procedure.

The automated test covers the following:

  • Calling a LV created DLL.
  • Calling re-entrant VIs.
  • Testing sequences for LV Adapter from 3.0 and 3.1.
  • LV Environments (Runtime and development).
  • Process Models (Sequential, Parallel and Batch).
  • It exercises the sequence editor and the following operator interfaces:
    • CVI
    • C#
    • C++
    • VB .Net
    • LV Executable Old
    • LV Executable Majik Full
    • LV Executable Majik Simple
    • LV Source Code old
    • LV Source Code new full

Test Procedure


System Setup

  1. Use a clean WXP2 machine with latest patches.
  2. Install .NET Framework if using TestStand 3.5.
  3. Install the latest Perforce client
    • NOTE: If you're making frequent testing it may be a good idea to create a ghost image up to this point.
  4. Install latest LV Build (8.0 or later).
  5. Install the latest Driver CD from select the following items:
    • NI-DAQmx (8.0 or later)
    • Traditional NI-DAQ (7.4 or later)
    • FieldPoint (5.0 or later)
    • NI-Motion (7.1 or later)
    • NI-IMAQ (3.1.3 or later)
    • NI-488 (2.2.4 or later)
    • NI-VISA (3.4 or later)
    • IVI Compliance Package (2.3 or later)
  6. Install latest TestStand Build.
  7. Create a TestStand user with the same name as the Windows user and make it an administrator.  Configure TestStand for automatic login by checking the Station Option "Automatically Login Windows System User".
  8. Optional: Install latest CVI Build install the FD version.
  9. Copy the LVBuildValidation directory from \\TestStand\Tests\LVBuildValidation\<LV Version> on Perforce.

If the version does not exists, copy the latest existing version folder and rename it to the version you are trying to test.

  1. Mass compile all LV Vis on LVBuildValidation directory
    • NOTE: You’ll need to make everything writeable on this directory.
  2. Update the Express VI instances in the sequence files

\\TestStand\Tests\LVBuildValidation\<LV Version>\Automated\Express VIs\Call All Non-Hardware Express VIs.seq

\\TestStand\Tests\LVBuildValidation\<LV Version>\Automated\Express VIs\ValidateExpressVIs.seq (Note: You'll need to manually update TickCount, Wait, WaitUntilNextMultiple steps)

\\TestStand\Tests\LVBuildValidation\<LV Version>\Automated\PartialClusterTesting\partial cluster passin\Partial Cluster Passing2.seq

You can use the sequence in //TestStand/Tests/LV Automated Tests/Framework Files/RefreshExpressVIs/Refresh Express VIs.seq to update those sequence.  Just update the parameter SequenceFilePath of the sequence file Refresh Express VIs.seq with the path of the sequence file that contains the Express VI instances.  If you are using 4.1, you can use the Update VI Calls tool.  Make sure to check the status messages for any problems.

Create the folder c:\temp to avoid getting a permission error when running in Windows XP and Windows 7.

  1. Rebuild the LV dll found in //TestStand/Tests/LVBuildValidation/<LV Version>/Automated/LVDLL/myDLL.dll.  If you don’t build this DLL, you find see a problem with the .NET references tests.
  2. Either Install the LV 6.1 Runtime Engine or rebuild the LVStructTest.dll (the LV 6.1 RTE is not installed by TS4.0 or above and will cause a crash).
  3. Copy the Util directory from //TestStand/Tests/Utils/ on Perforce.
  4. Be sure that you have a TestStand - Default Values <xx>.llb file where <xx> corresponds to the version of LabVIEW you are testing. This file should be in <TestStand>\AdapterSupport\LabVIEW.  Only the major and minor versions are used so, for example, LV 8.5 and LV 8.5.1 both use TestStand - Default Values 85.llb!  Be sure to mass compile this llb.  
  5. Import the file //TestStand/Tests/LVBuildValidation/<LV Version>/Automated/MiscVIs/DAQmx Task VIs/configData.nce.
  6. Open the project //TestStand/Tests/LVBuildValidation/<LV Version>/Automated/MiscVIs/BlockDiagramRemoved/RemoveBlockDiagram.lvproj and build the Build Specification “Remove Block Diagram.”  This is needed to rebuild the VI without its block diagram.  The VI gets called as part of the overall test.
  7. If testing LV 9.0 or later, rebuild the LV built assembly found in //TestStand/Tests/LVBuildValidation/<LV Version>/Automated/MiscVIs/LV Created Assembly/Assembly/LVCreatedAssembly.dll.
  8. Finally, rebuild the executables of the LabVIEW Full-Featured and Simple UIs (in <TestStand Public Directory>) with the LV version being tested to avoid getting a crash when executing the test VIs that test the .NET references (see CAR 114668 for details)

Test

  1. Rebuild the .dll found on LVDLL.
  2. Launch TestStand and run AllLVBuildValidation.seq, select small on the dialog that appears.
  3. Run ValidateOI.seq on the Full-Featured LV UI when running in the LabVIEW Development System.
  4. Run ValidateOI.seq on the Simple LV UI when running in the LabVIEW Development System.
  5. Run ValidateOI.seq on LV Majik OI using the source code.
  6. Run ValidateOI.seq on Old LV OI using the source code if present in the TestStand version you're testing with.
  7. Run ValidateOI.seq on Old LV OI using the executable, that's the 2.0.1 OI if present in the TestStand version you're testing with.
  8. Report your results.

Note: Make sure to run ValidateOI.seq with a LV UI in LV since we have discovered several problems this way.
