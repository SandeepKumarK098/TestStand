Test Case Scenario
National Instruments Confidential

.NET Adapter

Adapters



Test Description

 

Test all possible options. Look at the adapter documentation to help you better understand all the options available.

Test Procedure

Note: As of TestStand 2010 Measurement Studio is no longer required for debugging or create/edit code operation.  You should run these tests on a machine without Measurement Studio to verify that it is no longer required.

  • NET Adapter Debugging
    • Setup
      • Use the Visual Studio that is supported for the release you are testing (3.x - VS.NET 2003, 4.0 VS.NET 2005) to create a C# and/or VB.NET DLL
      • Create both functions and properties
      • Create overloaded functions (this is required to test the majority of the code - without overloads an optimization eliminates most of the token lookup code)
      • Make overloads use various complex data types such as multidim arrays, user defined types, etc. Be creative.
      • Make .NET steps that make multiple sequential calls on the same step.
    • Basic functionality
      • Verify step into and step over work as expected
      • Verify step into followed by step out stops on next step in sequence.  If you have more calls on your step, step out will stop on the same step, and then step into should step into the next call.
      • Verify step into followed by continue does not stop on next step in sequence
      • Verify prompt if attempt to stop debugging or exit VS.NET
      • Repeat above with VS.NET debugger already attached to SeqEdit.exe (specify SeqEdit as the debugging .exe for the VS.NET DLL)
      • Verify developing/debugging/rebuilding process works intuitively for VS.NET DLL steps
      • Verify that if you step into a step that first calls an implicitly defined constructor, TS will just skip over the constructor and not give an error.  Verify that if you step into a step that first calls an explicitly defined constructor, TS properly steps into the constructor and does not skip it.
      • Things to think about include switching of top level application and performance
      • Verify that you can step through each call on a multi-call step and that none of the calls get skipped.
    • Corner and failure cases
      • Test with .NET debugging disabled in VS.NET
      • Kill VSDebuggingController.exe at various stages of debugged execution
      • Set various types of breakpoints at various places (especially the first line) in the method/property and verify it is not removed
      • Try multiple executions or threads calling different functions and calling the same functions
      • Try stepping into a CVI-created function while debugging from VS.NET
      • Try stepping into a release-compiled VS.NET DLL
      • Move or rename the source file containing the method/property
      • Test throwing an exception from code you stepped into
      • Verify no debugging functionality with version of Visual Studio that is different from the supported version.
      • Test using a class that contains properties with one public accessor and one private accessor. Make sure there are no edit time errors when selecting these properties.

·         Open the sequence file found in this zip file and on the .NET step, from the method selection dropdown, select the "get_Abc" method. Verify that there are no errors.

  • Test Create/Edit code in the .NET adapter
    • Test with various combinations of all versions of VS (2003 and newer) installed on the machine.
      • Create and edit code should only work for project/solution files from the supported version of VS (3.x - 2003, 4.0 and 4.1 - 2005). TS 4.2 supported VS 2005 and 2008 and attempted to support future versions as well.  TS 2010 supports VS 2005, 2008, 2010 and attempts to support future versions.  If there are future versions of VS that are not yet supported by the version of TS you are testing, you should still do some minimal testing to see what does and does not work.
    • Create Code
      • Verify that the browse buttons browse for the correct type of file and that the edit controls are correctly updated when a file is selected.
      • Test Create Code using various source, project, and solution files.
      • Verify that if no solution file is provided, an appropriate solution is used.
      • Verify that if the solution file is already open in a Visual Studio environment, that environment is used for code generation.
      • Verify that you browse for the files if they do not exist.
      • Test functionality when the desired function already exists in source.
      • Verify that a replace/insert above/insert below dialog is displayed and that the correct action is taken depending on the user's choice.
      • Verify that the code template is correctly read and that any using statements, parameters types and names, and function body are transferred to the new function.
      • Test with methods that use various parameter types (structs, enums, nested types, etc).
      • Do all tests with both C# and VB as there is completely different code for the code generators for the two languages.
    • Edit Code
      • Test Edit Code using various source, project, and solution files
      • Verify that if no solution file is provided, an empty solution is used (TS 3.0 Beta 2 requires a solution).
      • Verify that if the solution file is already open in a Visual Studio environment, that environment is used for code generation.
      • Verify that an error message is displayed if the function does not exist in the source.
      • Verify that the project and source are opened and that the cursor is moved to the first line of the correct function.
      • Test with methods that use various parameter types (structs, enums, nested types, etc).
      • Test with constructors.
      • Do all tests with both C# and VB as there is completely different code for the code generators for the two languages.
  • Other tests
    • Test Specify Module Dialog for both classes and structs
    • test with all parameter types, with keywords ref and out,
    • Test Specify Constructor Dialog for both classes and structs
    • test with all parameter types, with keywords ref and out,
    • Run automated test to test passing all valid data types
  • Standard Test for Adapters
  • Standard Test for Dialogs
