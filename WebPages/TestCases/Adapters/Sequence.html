Sequence Adapter

Sequence Adapter

Adapters


Test Description


Test all possible options. Look at the adapter documentation to help you better understand all the options available.

Test Procedure


  • Test passing numeric, string, boolean, and object parameters.
  • Test passing user defined types like UUT
  • test passing arrays of all types
  • Test passing by value and by reference
  • Test typechecking feature
  • Test parameter error reporting
  • Standard Test for Adapters
  • Standard Test for Dialogs
  • CARs
    • CAR 50951 -- Test the flags in the Sequence Call Advanced Settings dialog that overlap with the Additional Execution Type Mask Settings. Make sure that the behavior is the logical OR of the checkboxes and the flags.
      • "Use Single-Threaded Aparentment" checkbox vs. ExecTypeMask_UseSTA (This was the item from the CAR.)
      • "Initially Suspended" checkbox vs. ExecTypeMask_InitiallySuspended
      • "Initially Hidden and Disable Tracing" vs. ExecTypeMask_InitiallyHidden and ExecTypeMask_TracingInitiallyOff
      • "Close Window When Done" vs. ExecTypeMask_CloseWindowWhenDone
      • "Restartable" vs. ExecTypeMask_NotRestartable (Note, this one is checked by default and the flag is equivalent to unchecking it.)
    • CAR 638961: Revalidate CAR 638961. (There are full steps to reproduce in the CAR.) Specifically, make sure that if you reorder the parameters in a target sequence file, when you open the calling step in an OI, "Specify Module...", and OK all the way back to the sequence, that file is modified and the call works properly. You should also get a warning dialog, much as you would if the number of parameters had changed.

      The root cause of this CAR was that we were not treating the order of the actual arguments as important. (We were not passing kRequireIdenticalStructure to IsEqualTo()). Before the fix, we were updating the prototype when the order changed, but not the actual args. With the fix, we update both.

      Briefly test around the fix. For example, verify that changing a parameter name without changing the order, adding a parameter, removing a paremeter, etc. work as expected. Verify that when nothing is changed, pressing OK (without making other changes) does not caues the file to be marked dirty. Also, although neither the CAR nor the fix involved the step settings panel in the Sequence Editor, make sure the Sequence Editor does not have the bug as well.
